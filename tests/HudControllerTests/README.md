# Managed controller transition checks

Run `dotnet run --project tests/HudControllerTests/HudControllerTests.csproj -c Release`. The runner invokes private methods on the actual compiled WeaponPaints controller; it does not reproduce the controller logic in a mock. It uses an uninitialized plugin object to avoid calling native CounterStrikeSharp initialization, managed controller/session data and the real session coordinator with a managed surface stub to test dirty edit navigation, picker confirmation, team changes, save guards, controls, prompt lease ownership/expiry, and disabled/enabled alias routing when no player is supplied, plus the real `RouteHudAliasSession` dirty-picker, busy and prompt branches the actual Steam/controller ownership predicate, conflict Stay/Reload failure with draft retention, stale query generation and deferred Apply while returning from a picker.

This is not a CounterStrikeSharp host test. It does not instantiate native player controllers, register real listeners, deliver chat/click events, test alive/dead players, or exercise a database write through the controller. Real slot ownership and native input still require an isolated game-server test or an explicitly extracted controller seam.
